# G2.2 - DESIGN Generator

## Implemented scope

A standalone deterministic UI/UX design generator is available through
the local Python CLI and a local MCP tool. It does not invoke a model,
open a browser, render screenshots, run JavaScript, fetch URLs or
publish a deployed prototype.

- **Markdown design spec**: audience, objective, style, information
  hierarchy, named component inventory, responsive sizing, accessibility
  requirements, source references and acceptance checklist.
- **Static HTML preview**: self-contained HTML/CSS, semantic heading/main
  landmarks, light/dark color scheme, 640px and 960px layout rules,
  reduced-motion CSS and bounded user text escaping.
- Layout families: `dashboard`, `landing`, `form`, `catalog`.
- Responsive strategies: `mobile-first`, `desktop-first`.
- Component allowlist: `header`, `navigation`, `hero`,
  `summary`, `cards`, `filters`, `form`, `footer`.
- Output MIME: `text/markdown` or `text/html`. No SVG, PNG,
  Figma project, React app, functional workflow or client-side JavaScript
  is generated by this milestone.

The built-in HTML template is an inspectable **static prototype**.
All control-looking regions are labeled as non-interactive. A real
responsive browser session, contrast audit, keyboard navigation,
screen reader audit and interaction testing remain separate gates.
The template is **not** a guarantee of WCAG compliance.

## CLI

From the project root:

```powershell
python -m generators design --objective "Signal research dashboard" --audience "Analysts" --layout dashboard --responsive mobile-first --authorize-create
```

Export a static HTML preview to an existing directory (exclusive
creation; refuses overwrites):

```powershell
python -m generators design --objective "Signal research dashboard" --layout dashboard --format html --authorize-create --export-root . --filename design-preview.html
```

Do not place generated files or large media into the public Git
repository by default; choose a dedicated local export directory for
reusable assets. A generated HTML file can be inspected in a local
browser, but the CLI and automated tests do not assert a browser has
been used.

## MCP

The local MCP server advertises the additive `generate_design`
tool with a bounded JSON schema. It accepts `objective`, optional
`audience`, `style`, `sources`, `constraints`,
`verification`, `layout`, `responsive`, `components` and
`format` (`markdown` or `html`). It requires a trusted
`--allow-create` server grant. Neither tool inputs nor Markdown
sources can grant permission.

Default MCP discovery contains 10 tools; with the optional ComfyUI
image tool enabled, it contains 11. The existing nine tools retain
their names and behavior. The new design tool returns in-memory
text with a typed manifest and explicit `output_verified: false`.
It does not export HTML through MCP.

## Validation and acceptance

- Requests are bounded, component names are allowlisted, unknown
  fields and duplicate components fail closed.
- User text is escaped before inclusion in Markdown or HTML.
- Generated HTML forbids script elements, event-handler attributes
  and external resource URLs. No external fonts, images, CSS or
  JavaScript are emitted.
- Local exports create a new file exclusively and verify bytes
  and SHA-256. Existing files are never overwritten.
- CI tests cover four layouts, determinism, denied permissions,
  unsupported output/provider, escaping, prototype checks, CLI,
  export and MCP tool contract.
- `structural_validation: passed` does not mean browser/UX review,
  accessibility certification, visual-design approval or interactive
  functionality.

Future milestones may add a verified product-design provider,
working controls, editable component sources, snapshots and browser
automation, subject to separate permission and acceptance requirements.
