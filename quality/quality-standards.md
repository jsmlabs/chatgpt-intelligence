# Quality Standards

## Required
1. **Correctness:** No invented facts, tests, citations, features, or outcomes.
2. **Completeness:** Address the actual user or reader objective.
3. **Traceability:** Date and cite claims about changing product behavior.
4. **Clarity:** Explain concepts before details; define unfamiliar terms.
5. **Consistency:** Preserve the project's names, scope, and canonical links.
6. **Appropriate presentation:** Use visuals and interactions only when they add value.
7. **Safety and privacy:** Avoid secrets, personal memory exports, and unnecessary personal details.

## Review result
Use `passed`, `failed`, `blocked`, or `not-run` for actual checks. A draft that has not been checked must not be presented as verified.

## Critical failures
A fabricated citation, a false claim of an implemented feature, an exposed secret, or an unverified claim of successful testing blocks acceptance regardless of formatting quality.

See [evaluation guidelines](evaluation-guidelines.md).
